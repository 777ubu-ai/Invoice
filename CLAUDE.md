# Invoice — TNVED.ai Telegram Bot

## Контекст проекта

Telegram-бот **@InvoiceAgentsBot** для казахстанского таможенного брокера.
Принимает китайские packing list (xlsx), классифицирует товары по ТН ВЭД ЕАЭС,
выпускает готовый таможенный инвойс в формате LINEA TRANSIT.

Клиент: Бахитжан (777ubu), Казахстан. Команда: Шакен (MANAGER), Алихан (OPERATOR).

## Архитектура 5-агентного pipeline

1. **Переводчик** — извлекает позиции из xlsx, переводит с китайского
2. **Классификатор** — подбирает 10-значный код ТН ВЭД ЕАЭС + ставку
3. **Ревьюер** — confidence 0-100, флагает позиции с confidence <50
4. **Лаура** (финансист) — стоимость, пошлина (по ставке), НДС 16%, сбор 26 000 KZT ≈ $54
5. **Маке** (главный) — финальная приёмка, валидирует суффиксы кодов

Модель: `claude-opus-4-7`. Prompt caching включён на system-промптах каждого агента.

## Внешние справочники / источники

- **https://www.ifcg.ru** — рабочий справочник ТН ВЭД ЕАЭС который использует
  таможенный брокер заказчика. Используй его как референс для валидации кодов.
  ⚠️ Из remote-environment сайт недоступен (host not in allowlist). Парсить
  можно либо с локальной машины пользователя, либо взять открытую базу
  с GitHub и положить в `bot/data/tnved-codes.csv`.

## Правила бизнеса (Казахстан, LINEA TRANSIT)

- Ставка цены для LINEA TRANSIT: **$0.75/кг нетто**
- Нетто = 95% от брутто (если нетто не указан)
- НДС РК: **16%** на (стоимость + пошлина)
- Таможенный сбор: **26 000 KZT** = **$54.17** при курсе 480 KZT/$
- Формат выходного инвойса: должен 1-в-1 совпадать с шаблоном `0005229.xlsx`
  (header + items table сгруппированная по кодам + ИТОГО + блок налогов)

## Что НЕ делать

- Не возвращать canned/mock данные при сбое — кидать ошибку с понятным текстом
- Не отправлять инвойс без стоимости (Лаура hard-fails)
- Не отправлять инвойс без одобрения Маке (Маке hard-fails при cost = 0 или нулевых позициях)
- Не угадывать 10-значные суффиксы ТН ВЭД — использовать только стандартные
  окончания (0000, 9000, 9009, 0009, 9900, 0090) если не уверен
